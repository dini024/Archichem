ORCA DOCKER Workbench

Prepare automated host–guest docking inputs, inspect ORCA DOCKER output files, compare optimized docking candidates, and visualize generated structures.

Important distinction: ORCA DOCKER is ORCA's energy-driven automated molecular docking algorithm. It is not Docker Desktop, a container, or a cloud service. This page analyzes files produced by an ORCA DOCKER calculation; it does not run ORCA inside GitHub Pages.

1. How ORCA DOCKER works

ORCA DOCKER searches for favorable arrangements when a guest molecule approaches a host structure. It evolves candidate arrangements on an energy surface, then performs final optimizations and reports optimized energies and interaction energies. The official ORCA 6.0 tutorial demonstrates this workflow with GFN2-xTB and GFN-FF.

! XTB PAL4

%DOCKER
    GUEST "guest.xyz"
END

*XYZFILE 0 1 host.xyz

Input interpretation: ! XTB requests the xTB method; PAL4 requests four parallel processes where supported; GUEST specifies the guest structure file; *XYZFILE 0 1 host.xyz defines the host coordinates, total charge 0, and spin multiplicity 1. Adapt the method, charge, multiplicity, and DOCKER settings to your chemical system.

The official tutorial notes that DOCKER is not fully parallelized in ORCA 6.0. Large systems can therefore remain computationally demanding. Read the ORCA 6.0 DOCKER tutorial.

2. Run ORCA DOCKER on your HPC or workstation

Prepare the host and guest coordinates as separate XYZ files, then create an ORCA input file referencing them. Run ORCA 6.0 or a compatible version from your licensed installation.

module load nuclear/orca/6.1.1
orca docking.inp > docking.out

For a cluster, follow local policy: use an interactive allocation for a short test or submit a suitable SLURM script for production calculations. Check your installed ORCA version and manual; do not assume every DOCKER keyword is identical across versions.

Typical files to retrieve after the calculation include docking.out, orca.docker.xyz, and orca.docker.struc1.allopt.xyz. The exact names depend on the input basename and calculation.

5. How to interpret the energy table

  • Eopt (Eh): optimized total energy of the docked complex as reported in the final optimization table.
  • Interaction energy (kcal/mol): interaction metric reported by ORCA DOCKER for each optimized candidate. Use this column to identify favorable host–guest arrangements within the same docking calculation.
  • Relative interaction energy: the candidate interaction energy minus the lowest interaction energy in that same output file.
  • Lowest interaction energy: the most favorable candidate according to the DOCKER interaction-energy metric, not necessarily the smallest raw total energy across unrelated systems.

Scientific caution: DOCKER is a structure-generation and screening method. Its xTB/FF energies are useful for exploring candidate arrangements, but final conclusions may require higher-level optimization, solvent treatment, basis-set checks, and appropriate thermodynamic analysis.
