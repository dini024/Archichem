ORCA on HPC: End-to-End Training Terminal

Practice a realistic workflow: create a remote working directory, transfer water.inp, inspect ORCA modules, write a SLURM script with nano, submit it, monitor the job, and extract scientific results.

Browser-only educational simulation. No remote connection, no real SLURM scheduler, and no ORCA calculation is performed. The job states and water.out values are illustrative training data. Confirm actual module names, partitions, and resource policies with your HPC administrator before using a real system.

Guided workflow

  1. Connect: ssh student@login.hpc.example.edu
  2. Create remote folder: mkdir -p ~/orca_training/water
  3. Return to laptop: exit
  4. Transfer input: scp water.inp student@login.hpc.example.edu:~/orca_training/water/
  5. Reconnect and enter folder: ssh student@login.hpc.example.edu, then cd ~/orca_training/water
  6. Inspect files and modules: ls -lh, module avail
  7. Load ORCA: module load nuclear/orca/6.1.1, then module list. Check the executable with which orca.
  8. Test the input without SLURM first: run orca water.inp > water.out (or a verified absolute executable path). Wait for the foreground command to finish, then inspect water.out.
  9. Create the SLURM script: nano run_orca.slurm. Save and exit.
  10. Verify files: ls -l. Submit: sbatch run_orca.slurm
  11. Monitor: squeue -u student; inspect: scontrol show job JOBID; history: sacct.
  12. After completion, inspect water.out using the four grep commands below.

Quick commands

Test ORCA directly before using SLURM

After loading the module and entering the working directory, test the input in the foreground without creating or submitting a SLURM file:

module load nuclear/orca/6.1.1
which orca
orca water.inp > water.out

If the administrator confirms the executable path, the absolute-path form is:

/mgpfs/apps/nuclear/apps/orca/6.0.1/orca water.inp > water.out

Version warning: the module command selects ORCA 6.1.1, but the absolute path points to ORCA 6.0.1. These are different versions. Also, the supplied command /mgpfs/apps/nuclear/apps/orca/6.0.1/orca orca water.inp > water.out has an extra orca argument after the executable. Standard ORCA usage normally places the input filename immediately after the executable. Do not use the doubled form unless the HPC administrator documents that syntax.

Command breakdown: /mgpfs/apps/nuclear/apps/orca/6.0.1/orca is the full path to the ORCA executable/launcher; it bypasses the executable selected through the module environment. water.inp is the input file. > water.out redirects standard output into the file water.out. This is a foreground calculation, so the terminal remains occupied until it exits. On a shared cluster, only run it on a permitted test/login node or within an interactive allocation, following HPC policy.

SLURM script example

#!/bin/bash
#SBATCH --job-name=water_opt
#SBATCH --partition=short
#SBATCH --nodes=1
#SBATCH --ntasks=4
#SBATCH --time=00:30:00
#SBATCH --mem-per-cpu=2G
#SBATCH --output=water_%j.out
#SBATCH --error=water_%j.err

set -euo pipefail
module purge
module load nuclear/orca/6.1.1
cd "$SLURM_SUBMIT_DIR"
export OMP_NUM_THREADS=1
orca water.inp > water.out

These are illustrative settings. The correct partition, module path, memory policy, and ORCA parallel launch command depend on the HPC installation.

Extract results from water.out

grep "ORCA TERMINATED NORMALLY" water.out
grep "OPTIMIZATION RUN DONE" water.out
grep "FINAL SINGLE POINT ENERGY" water.out
grep -A 4 "Total Dipole Moment" water.out

The final energy is reported in Hartree (Eh). The dipole moment is commonly reported in Debye. Always check normal termination and inspect the full output before interpreting values.
